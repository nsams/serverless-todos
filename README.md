# serverless-todos

Minimal todo app: TanStack Start on Cloudflare Workers, MUI + DataGrid, Drizzle, login via Cloudflare Access (Entra ID).

The app runs only on Cloudflare (Workers + D1). Locally it runs in the real Workers runtime (workerd) via `@cloudflare/vite-plugin`, D1 is emulated by Miniflare as a local SQLite database in `.wrangler/state/` (no Docker or external database needed).

## Setup

```bash
./install.sh
```

## Development

```bash
npm run dev  # applies pending migrations to the local D1, starts the app (http://localhost:5180)
```

Processes are managed by [dev-process-manager](https://www.npmjs.com/package/dev-process-manager) (`npx dev-pm status`, `npx dev-pm logs`, `npx dev-pm stop`).

Cloudflare Access is simulated locally by the Workers runtime (`access.dev`, configured in `vite.config.ts`): every request is authenticated as `DEV_USER_EMAIL` (`.env`). To work as another user, set `DEV_USER_EMAIL` in `.env.local` and restart `npm run dev`. There is no login/logout locally (the logout button leads to a 404).

The local D1 database can be browsed and queried in the Cloudflare Local Explorer at http://localhost:5180/cdn-cgi/explorer (while `npm run dev` is running), or from the command line:

```bash
npx wrangler d1 execute DB --local --command "SELECT * FROM todos"
npm run db:reset  # delete the local database and re-apply all migrations
```

## Structure

- `src/routes/`: file-based routes; `src/routeTree.gen.ts` is generated by the TanStack Start Vite plugin on `dev`/`build` (committed, so `tsc` works without a build)
- `src/routes/index.tsx`: todo list; grid state (pagination, sorting, filtering) lives in the URL (`src/todoSearch.ts`, serialized as plain search params by `src/searchParams.ts`)
- `src/todos.functions.ts`: server functions (data loading and mutations)
- `src/server.ts`: worker entry, passes `ctx.access` (Cloudflare Access) to the app as request context
- `src/start.ts`: global request middleware that rejects every request not authenticated by Cloudflare Access (`src/auth.server.ts`) and passes the user (identified by email) to the server functions as context

## Authentication

There is no login logic in the app: Cloudflare Access sits in front of the worker like an authenticating reverse proxy, lets users sign in with Entra ID and only forwards authenticated requests. The app rejects requests not authenticated by Access (`src/auth.server.ts`) and uses the user's email as user id:

- In production it verifies the Access JWT in the `Cf-Access-Jwt-Assertion` header (signature against `${ACCESS_TEAM_DOMAIN}/cdn-cgi/access/certs`, issuer and audience `ACCESS_AUD`). [`ctx.access`](https://developers.cloudflare.com/workers/configuration/cloudflare-access/) is not available there: workers with static assets run behind an internal router worker that doesn't pass it on.
- Locally it uses `ctx.access`, simulated by the Workers runtime (`access.dev`).

Denied requests are logged with the reason (Workers Logs).

## Database

Cloudflare D1 (SQLite) with Drizzle: schema in `src/db/schema.ts`, repository in `src/db/todos.server.ts`, migrations in `drizzle/`.

After changing the schema:

```bash
npm run db:generate  # generates a migration into drizzle/
npm run db:migrate   # applies it to the local D1 (also done on `npm run dev`)
```

## Deployment (Cloudflare)

Deploy with `npm run deploy` (build, deploy, apply pending D1 migrations), either locally or with [Workers Builds](https://developers.cloudflare.com/workers/ci-cd/builds/) (Git integration): leave the build command empty and set the deploy command to `npm run deploy`.

1. The D1 database doesn't need to be created manually: `wrangler.jsonc` has no `database_id`, so the first `wrangler deploy` creates a database named `serverless-todos` (or connects to an existing one with that name).
2. Set up Cloudflare Access (Zero Trust dashboard):
    1. Add Microsoft Entra ID as identity provider (Settings → Authentication → Login methods), see the [Cloudflare docs](https://developers.cloudflare.com/cloudflare-one/identity/idp-integration/entra-id/).
    2. Protect the `workers.dev` URL: Workers & Pages → serverless-todos → Settings → Domains & Routes → `workers.dev` → Enable Cloudflare Access. This creates an Access application for the URL (preview URLs are disabled in `wrangler.jsonc`).
    3. Edit that Access application (Zero Trust → Access → Applications): use Entra ID as the only login method and a policy that allows the intended users (e.g. an Entra group or email domain).
    4. Set `ACCESS_TEAM_DOMAIN` (`https://<team-name>.cloudflareaccess.com`, see Zero Trust → Settings → Team name and domain) and `ACCESS_AUD` (the Application Audience (AUD) Tag on the application's overview) in `wrangler.jsonc`.
3. Deploy: `npm run deploy`
